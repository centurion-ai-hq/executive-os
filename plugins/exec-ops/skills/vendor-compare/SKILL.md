# Vendor Comparison

Compares your real options on what actually matters, prices them honestly, and tells you which one to pick.

## When this fires

• The user names two or more tools, vendors, or services they're choosing between.
• The user says "compare these", "which one should I pick", "is X worth it over Y".
• A purchase or renewal decision is coming up and the options need a real look.

## What you do

1. Get the options and the actual decision context: what the tool needs to do, who uses it, and any hard constraint (budget ceiling, integration requirement, compliance need).
2. Decide the criteria that actually decide this choice, not a generic feature checklist. Usually 4 to 6: total cost, the one capability that matters most for this use case, switching cost from the current tool, support quality, reliability track record. State the criteria before scoring.
3. Research real, current pricing and capability for each option using web search. Do not rely on memory for pricing; prices change and a stale number makes the comparison worthless. Cite what you found.
4. Score every option honestly against the stated criteria, including the option the user seems to already favor. If the favorite loses on a criterion, say so plainly rather than softening it.
5. Calculate total cost over 12 months for each option: list price, any setup or migration cost, and any per-seat or per-use scaling the user's stated volume would trigger.
6. Give one committed recommendation: the option to pick, the runner-up, and the specific condition that would flip the recommendation, a price change, a volume threshold, a missing feature getting added.

## Output

• **Criteria used:** the 4 to 6 that actually decide it, stated plainly.
• **Comparison table:** option, score per criterion, 12-month total cost.
• **Recommendation:** committed pick, one sentence why.
• **Runner-up:** the second choice, and what it would take for it to win instead.

## Rules

• Price and capability claims must come from research done now, not assumed from memory. Say when a figure could not be verified.
• Score honestly, including against the option the user already likes. A comparison that always confirms the user's existing lean isn't a comparison.
• This skill recommends. Signing up, subscribing, or spending against any option needs the user's explicit go-ahead first, every time.
