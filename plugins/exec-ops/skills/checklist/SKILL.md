# Run Checklist

Turns a plan into a numbered list you can work from line by line, not a document you have to interpret.

## When this fires

• The user hands over a plan, process, or launch and needs something to execute from directly.
• The user says "make this a checklist", "turn this into steps", "give me a run sheet".
• A task needs to be handed to someone else to execute without further explanation.

## What you do

1. Read the plan, process, or launch description provided.
2. Break it into discrete, sequential line items. Each item is one action, not a bundle of several. If a step has more than one real action inside it, split it.
3. For every line, write a do-criterion: the exact trigger or starting condition for that step, what has to be true before it starts.
4. For every line, write a done-criterion: the exact, checkable condition that proves the step is finished. "Done" must be something you can look at and confirm yes or no, not a feeling.
5. Assign an owner to every line. If the user has not said who, ask once for the list of people involved rather than leaving owner blank on every line.
6. Add a pass/fail check to every line: the single fact to check to know if this step actually worked, separate from just having been performed.
7. Number every line. Strip explanatory prose; this document is worked from, not read for understanding. Keep any needed context in one short note block at the top, not woven through the steps.

## Output

A numbered list, one row per step:
`# | Step | Do when | Owner | Done when | Pass/fail check`
A short context note above the list only if needed, no longer than two sentences.

## Rules

• Every line must have a checkable done-criterion. "Done" that can't be verified isn't done.
• No owner left blank. If it is genuinely unassigned, write "unassigned, needs owner" rather than leaving it empty.
• This document stays terse. If an explanation is needed, it belongs in a separate reference, not in the checklist itself.
• Building the checklist is free. Any step that sends, publishes, spends, or deletes still needs the user's go-ahead at that step, called out inline.
