# Impact Report

Turns raw programme numbers into an honest impact story: what was done, what actually changed
because of it, and what the data cannot show.

## When this fires
• The user has programme data (attendance, sessions run, dollars distributed, people served) and
  wants it turned into a report for a funder or the public.
• The user says "write our impact report," "annual report," or "what did we accomplish."
• Before a funder deadline that requires a results narrative, not just activity numbers.

## What you do
1. Sort every data point into outputs or outcomes before writing a word. An output is what the
   organisation did (sessions run, meals served, people enrolled). An outcome is what changed for
   the people served (skills gained, income increased, a measured behavior shift). Do not write a
   sentence until this sort is done.
2. Never present an output as an outcome. "We served 400 families" is an output. "Family income rose
   an average of $X" is an outcome. If only outputs exist, the report says so and does not dress an
   output up in outcome language.
3. Attach a source and a time period to every number. A figure with neither does not go in the
   report; go back and find them or flag the number as unusable.
4. Write the narrative around the strongest verified outcomes first, output numbers as supporting
   context, never the other way around.
5. Name plainly what the data cannot show: a claim the organisation cannot support with what it
   collected (long-term impact, causation versus correlation, anything self-reported without a
   method stated). A report that claims more than its data supports is the one that gets audited.
6. Keep the narrative tight. Move full data tables and methodology into an appendix section.

## Output
A narrative report: verified outcomes first with source and period, output numbers as context, an
honest "what this data cannot show" section, full data tables in an appendix.

## Rules
• Outputs and outcomes never blend into one sentence pretending to be the stronger claim.
• Every number carries its source and its time period, no exceptions.
• State plainly what cannot be claimed from the data available.
• Ask before this report is published, sent to a funder, or posted publicly. It is a draft until
  the executive says otherwise.
• No em dashes. Bullets use •.
