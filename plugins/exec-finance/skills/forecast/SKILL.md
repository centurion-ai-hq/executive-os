# Cash and Revenue Forecast

Projects the numbers forward from what the executive actually knows today, so a decision can be
made before the money runs thin, not after.

## When this fires
• The user gives current cash, revenue, or expense figures and asks what happens over the next
  weeks or months.
• The user says "forecast the next quarter," "will we run out of money," "project revenue," or
  "model this out."
• Before a hiring, spending, or pricing decision that depends on what cash looks like ahead.

## What you do
1. Ask, one question at a time, for whatever inputs are missing: current cash on hand, expected
   revenue and its timing, fixed costs, variable costs, and any known one-time items ahead.
2. State every assumption used, on its own line, labeled as an assumption. "Assuming revenue holds
   flat at $X/month" is an assumption. Never fold an assumption into a number silently.
3. Build two cases, never one: a base case using the numbers as given, and a downside case using a
   deliberately worse but stated variation (slower collections, a lost account, higher costs). Name
   what changed between the two.
4. Project month by month, not just an end figure. Show the running cash balance for each month in
   both cases.
5. Name the month, if any, where cash goes negative or below a safe minimum in each case. This is
   the single most useful line in the whole forecast.
6. Never present the output as a fact. It is a projection built from stated assumptions, and it says
   so in the output itself.

## Output
A table by month (revenue, expenses, net, running cash) for the base case and the downside case,
side by side or stacked. The assumptions list above the table. One line naming when things get
tight, if they do, in either case.

## Rules
• This skill analyses the executive's own business. It never gives personalised investment advice
  and never recommends where to put money outside the business. Asked for that, it says plainly it
  is not a licensed advisor and stops.
• Never smooth over a bad number to make the forecast look better. State it and move on.
• Label every assumption. An unlabeled assumption is the single fastest way this tool becomes
  dishonest.
• Ask before anything from this forecast goes to anyone outside the executive: an investor update,
  a bank, a board member. This tool projects, it does not send.
• No em dashes. Bullets use •.
