# Panel

Five operators argue the call from five different jobs. One chairman calls it.

## When this fires

• A decision is big enough that one point of view is not enough: pricing, hiring, a pivot, a new offer, a partnership.
• The user says "run the panel", "second opinion", "what would a board say", or names wanting real disagreement, not another yes.
• The user suspects everyone around them (including the assistant) is just agreeing with them.

## What you do

1. Get the decision as one clear question. If it is vague ("should we grow?"), ask the user to sharpen it to something a real board could actually vote on, then proceed.
2. **Spawn each viewpoint as a separate agent, in parallel.** Use the Task tool, one agent per
   seat, each given the decision and its own lens and nothing else. This is what makes the panel
   real: five genuinely independent readings, not one voice doing five accents. If the Task tool
   is unavailable, run them one at a time in sequence, and say in one line that you did so and
   that the independence is weaker as a result. Never quietly downgrade this step.
   • **The Product Purist:** does this deserve to exist, is it simple enough, does it feel premium or does it feel like a compromise.
   • **The Operator:** can the team actually execute this with the people and systems in place today, what breaks first.
   • **The Capital Allocator:** what does this cost, what does it return, is there a better use of the same dollar.
   • **The Growth Closer:** does this make the thing easier to sell, does it strengthen or dilute the pitch, what does a buyer actually hear.
   • **The Systems Engineer:** does this scale without breaking, what compounds and what has to be rebuilt in a year.
3. Collect all five verdicts. Strip any names or identifying phrasing and show each viewpoint the other four, anonymized, so no one knows which is which.
4. Give each viewpoint exactly one rebuttal: which of the other four arguments is weakest, and why. Disagreement is the point. If a viewpoint has nothing to add, it says so instead of manufacturing a complaint.
5. Read the full debate (five original verdicts, five rebuttals) and write one chairman verdict: the call, the two risks most likely to break it, and the one dissenting view worth keeping in mind even though it did not win.
6. Present the debate first so the user can see the disagreement, then the chairman verdict last, clearly separated, so it can be read on its own.

## Output

Two sections, in order:

• **THE DEBATE:** each of the five viewpoints' verdict, labeled, followed by its one rebuttal.
• **THE CALL:** one paragraph recommendation, the top two risks, and the dissent named: which viewpoint disagreed and why it still matters.

## Rules

• These are five ways of thinking about a decision, not five real people. Never present them as anything else.
• Anonymize before the rebuttal round. Skipping this turns the panel into an echo chamber, which defeats the purpose.
• A vague question gets sharpened before the panel runs, not after.
• The chairman verdict is one committed call, never a tie or a "could go either way."
• This skill only advises. Sending, spending, or publishing on the decision still needs the user's own go-ahead.
