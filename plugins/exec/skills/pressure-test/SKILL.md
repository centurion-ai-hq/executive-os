# Attack

Four angles hit the plan in order, then one report, so nothing gets missed and nothing drags on.

## When this fires

• The user is about to approve a plan, a budget, or a strategy and wants it pressure-tested first.
• The user says "pressure-test this plan", "grill this", "before I commit", or "pressure this".
• A plan has been sitting in the conversation and no one has actually argued against it yet.

## What you do

Run all four angles in order, on the same plan, before writing anything back. This is one drill,
not four separate skills. Do not narrate each angle as you go, hold every finding until the end.

1. **Restate the plan** in two or three sentences, in the user's own terms, so the report is
   provably attacking the real plan and not a guess at it.
2. **Angle A, the reality check.** List the facts and assumptions the plan actually rests on. For
   each one, say whether it is verified, a reasonable inference, or a guess dressed up as fact.
   Flag any assumption the plan would not survive being wrong about.
3. **Angle B, the strongest case it fails.** Build the real argument against this plan, not a mild
   caveat. If you cannot find a genuine one, say so plainly rather than manufacturing a weak one.
4. **Angle C, the over-engineering check.** Is this bigger, longer, or more complex than the goal
   actually requires. Name the simplest version that would still get the outcome, if one exists.
5. **Angle D, the money question.** What this costs, in dollars or hours, against what it returns,
   in dollars, time saved, or a stated outcome. If either side is unknown, say so, do not guess.
6. **Weigh all four together** and write one verdict: proceed, proceed with named changes, or stop.
   Never hand back four sets of findings with no call attached.

## Output

One consolidated report, in this order, nothing narrated in between:

• **The plan:** two or three sentences.
• **Reality check:** facts and assumptions, each labeled verified / inference / guess.
• **Strongest case against:** the real argument, or "none found" if it genuinely survives scrutiny.
• **Over-engineering check:** right-sized or bigger than it needs to be, with the simplest
  alternative named if one exists.
• **The money question:** cost against return, in numbers, or named as unknown.
• **Verdict:** proceed / proceed with changes / stop. If changes, name each one in one line.

## Rules

• Run all four angles before writing the report. No partial results, no play-by-play.
• Never soften a real objection to be agreeable, and never invent one where the plan is sound.
• Numbers over adjectives in the money question. "Costs 12 hours, returns $4,000" beats "expensive".
• This skill only judges. It never sends, spends, publishes, or executes the plan itself.
• If the verdict is "stop" or "proceed with changes", say what happens if nothing changes.
